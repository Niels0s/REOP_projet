High-level strategy
-------------------
1. Make the repair pipeline defensive.
   - Repair must compute the missing set internally and never assume the caller's list is correct. That removed a class of assertion failures.
2. Add diagnostics instead of aborting.
   - Emit feasibility diagnostics (`feasibility_issues`) and log warnings instead of aborting; this enables batch runs to complete and collect data.
3. Reduce forced singletons and improve insertion quality.
   - When inserting removed customers, consider changing the route's vehicle family to a larger one if that enables a feasible insertion.
   - Implement a bounded "displacement" local move prior to forcing singletons: attempt to remove one customer from a candidate route and reinsert the displaced customer elsewhere.
4. Improve local search and merging to reduce rental/fuel cost.
   - Evaluate relocates using vehicle re-selection for both source/destination (more accurate cost delta).
   - Increase inner VND iteration budget so local moves can cascade.
   - Add greedy pairwise route merge post-processing (try orientations + vehicle re-selection) to cut rental/fuel cost by reducing the number of routes.
5. Expose tunables via CLI and create tests to prevent regressions.
   - CLI: `--ils-iter`, `--ruin-fraction`, `--max-vnd-iter`, `--disable-merge`/`--enable-merge`, and later `--seed` (optional).
   - Tests: deterministic and randomized tests for ruin/repair invariants and a targeted insertion improvement test.

1) src/heuristics.jl
--------------------
This is the main file where the majority of algorithmic work occurs. Below are the specific changes and an explanation for why each was applied.

A. Repair (ruin/recreate) changes
- Function: `repair_solution(solution::Solution, instance::Instance)`
  - Now computes the expected missing set from the candidate solution itself:
    - `present_set = Set(present)` followed by `expected_missing = setdiff(all_ids, present_set)`.
    - Rationale: previously the repair sometimes relied on a caller-provided missing list; mismatch caused infeasible solutions and assertion failures.
  - Maintains `to_insert` as a Set of missing customers and iteratively tries to insert each.
  - Insertion improvement: when trying to insert into an existing route, the code enumerates candidate vehicle families that satisfy capacity for the route after insertion, and tries each family and insertion position. If an insertion is feasible for any family, it computes the cost delta using `calculate_ids_cost(..., family, instance)` and picks the best.
    - Rationale: allowed the algorithm to change the vehicle family for a route if that reduces cost or is necessary to accept the insertion. This reduces forced singletons because the route may be upgradable to accommodate the extra customer instead of creating a dedicated rescue vehicle.
  - Bounded displacement local rebalance: before forcing a singleton, the code attempts to insert the target customer into a route by displacing one existing customer (from the first up to 3 customers in the candidate route) and then reinserting the displaced customer elsewhere (existing routes or as singleton). Steps:
    1. For each candidate route `r` and each displacement candidate `disp_cust` among the first 3 customers:
    2. Try all positions for inserting the new `cust` into the route, remove `disp_cust` from the temporary route.
    3. Check route feasibility with candidate families that can carry the temporary load.
    4. If feasible, attempt to reinsert `disp_cust` in other routes via the same family-aware insertion test; if that fails, add `disp_cust` as a singleton with the smallest family that fits.
    5. If reinsertion succeeds, apply both changes and mark both customers as inserted.
    - Rationale: displacing a single customer can create room for the removed customer while sending the displaced customer to an alternative route, reducing forced singletons without broad recomputation.
  - Forced singleton fallback: when all attempts fail, adds the customer as a singleton route using the largest rescue vehicle (end of `instance.vehicles`) and records the event in diagnostics under `:forced_singletons`.
    - Rationale: guarantees feasibility but records the cost increase so we can diagnose and tune the algorithm.
  - Diagnostics: returns `diag = Dict(:inserted => collect(inserted), :skip_counts => skip_counts, :forced_singletons => forced_singletons)`.

B. Local search improvements
- Relocate operator (`local_relocate`) previously approximated cost by keeping the same vehicle families for both routes when evaluating the move. This limited acceptance of relocates that would become profitable only after re-selecting vehicle families.
- Change: when a feasible insertion into `routes[j]` is detected, the code recomputes the best vehicle family for both the reduced source route and the expanded destination route by calling `optimize_route_vehicle(...)`. It then computes cost `c_src` and `c_dest` with `calculate_ids_cost` for these optimized families and accepts the move when the true delta is negative (with a small tolerance).
  - Rationale: allows relocates that unlock cheaper vehicle choices, enabling more nationwide improvements which in turn enable merges.

C. Variable Neighborhood Descent (VND)
- `variable_neighborhood_descent(solution::Solution, instance::Instance)` now takes a parameter `max_iter::Int` and uses it as the loop budget (default increased to 20).
  - Rationale: small moves can cascade; increasing the budget gives the local operators more opportunity to find deeper improvements.

D. Greedy route merge (post-VND)
- Added function `greedy_route_merge(sol::Solution, instance::Instance)` and it is called after `variable_neighborhood_descent` within `vnd_heuristic` (unless disabled by the CLI flag `enable_merge=false`).
- Behavior: for every pair of routes, try the four concatenation orientations (A+B, A+rev(B), rev(A)+B, rev(A)+rev(B)), then for all vehicle families that can carry the merged load, test feasibility and accept merges that produce positive savings (rental+fuel+radius), applying the best merge per iteration and repeating until no merge yields improvement.
  - Rationale: greedy merges reduce the rental/fuel fixed costs by eliminating short routes when feasible. This contributed a significant part of the observed improvement below 30k.

E. Helper tweaks
- Vehicle optimization helper `optimize_route_vehicle(order_ids::Vector{Int}, current_fam::Int, instance::Instance)` is used throughout to choose the best vehicle family for a route given its order ids; this is now used more broadly in relocate, post-processing, and finalization.

F. Finalization & uniqueness
- `ensure_solution_uniqueness(solution::Solution, instance::Instance)` and a local `finalize_solution_unique` are used to remove duplicates and add missing customers as singletons only as a final rescue. Both return compact diagnostics and emit aggregated warnings rather than aborting.
  - Rationale: keeps pipeline non-failing while still reporting anomalies for offline debugging.

2) scripts/main.jl
------------------
The driver script was changed to provide better CLI control and non-aborting behavior:

- New CLI flags parsed and forwarded to `vnd_heuristic`:
  - `--ils-iter=<N>` : number of ILS iterations (default 50)
  - `--ruin-fraction=<f>` : fraction of orders to remove during ruin (default 0.15)
  - `--max-vnd-iter=<N>` : inner VND iteration budget (default 20)
  - `--disable-merge` / `--enable-merge` : toggle greedy route-merge post processing
  - `--verbose` / `-v` : enable debug logging

- Main loop changed to never abort on infeasibility. If `is_feasible(solution, instance)` returns false, we print diagnostic information (missing orders and duplicates) and continue processing other instances. The per-instance solution is still written to `data-projet/solutions` and the summary file `costs.txt` is updated.

- The `vnd_heuristic` call now receives the new flags and returns the final solution with the improvements described above.
